# 011 — v1.5.0 All-OS Release (Windows · macOS · Linux)

> First release to ship **all three platforms**. Base: `v1.4.1` (commit `1d109c8`, 2026-05-21).
> Linux is new this cycle and is delivered as an **AppImage via Velopack** — the same
> auto-update pipeline Windows and macOS already use.

---

## 1. Version

**`1.5.0`** — minor bump from `v1.4.1`.

Rationale: adds a whole new platform (Linux/X11), completes the **Blink Twice EyeRest**
rebrand, and ships macOS memory-leak/focus/positioning fixes plus Windows audio hardening.
No breaking changes for existing users → minor, not major.

Passed explicitly to every publish script (`X.Y.Z = 1.5.0`); `Directory.Build.props`
stays at the `0.0.0-dev` guard default and is overridden at publish time.

## 3. Linux signing & distribution — the decision

**Linux has no OS-level code-signing gatekeeper** (no Apple notarization / Windows
SmartScreen equivalent). Trust on Linux comes from the **distribution channel** (a signed
repo), not a per-binary certificate.

**This release (Phase 1): AppImage via Velopack.**
- Reuses the existing Velopack + GitHub Releases + R2 pipeline.
- `UpdateService` already uses `GithubSource` which auto-selects the `linux` channel by OS,
  and `VelopackApp.Build().Run()` is already wired in `Program.cs` → **no app-code changes**.
- AppImage is unconfined, so the existing X11 idle probe / `paplay` / `notify-send` / XDG
  autostart code runs unchanged.
- Integrity via the Velopack feed's SHA256 (`releases.linux.json`). Optional GPG signature
  on the AppImage can be added later; it is advisory only.

**Strategic follow-up (Phase 2, not in this release): Flathub.**
- Flathub signs its OSTree repo and lists the app in GNOME Software / KDE Discover — the
  real "signing + trust + discoverability" answer for Linux.
- Requires a flatpak manifest and adapting the sandbox-hostile bits (spawning
  `paplay`/`notify-send`, writing `~/.config/autostart`, tray, screensaver idle) to XDG
  portals / permission holes. Tracked separately; does **not** block this release.

Snap and per-distro `.deb`/`.rpm` repos are intentionally out of scope (more maintenance,
less reach than Flathub).

## 5. Build steps (per OS)

Artifacts from all three land in `releases/` on their own Velopack channel
(`win` / `osx` / `linux`) and merge onto the single GitHub tag `v1.5.0`.

### 5.1 Windows — locally (Azure-signed)

```powershell
.\scripts\publish-velopack-win.ps1 -Version 1.5.0
```
Verify: `Get-AuthenticodeSignature .\releases\*Setup.exe` → `Valid`, signer `CN=PMT Labs LLC`.

### 5.2 macOS — over SSH to the Mac (signed + notarized)

Host: `ssh tamtran@tam-mac.local` (password in `$env:MAC_PWD` on this box). Same repo on the
Mac at `~/sources/demo/eye-rest` — `git fetch && git checkout <release-ref> && git pull` first.

Non-interactive SSH gotchas (see rephlo guide `001-publish-release-guide.md`):
1. **Login shell** — run through `bash -lc "…"` so `dotnet`/`vpk` are on PATH.
2. **Unlock keychain** first, or `vpk pack` codesign aborts with `errSecInternalComponent`:
   ```bash
   printf '%s' "$MAC_PWD" | ssh tamtran@tam-mac.local 'IFS= read -r PW; \
     security unlock-keychain -p "$PW" ~/Library/Keychains/login.keychain-db && \
     security set-key-partition-list -S apple-tool:,apple: -s -k "$PW" ~/Library/Keychains/login.keychain-db && \
     security set-keychain-settings ~/Library/Keychains/login.keychain-db'
   ```
Then build:
```bash
ssh tamtran@tam-mac.local 'bash -lc "cd ~/sources/demo/eye-rest && \
  export PATH=\$PATH:\$HOME/.dotnet/tools && \
  SIGNING_IDENTITY=\"Developer ID Application: PMT Labs LLC (68M75D67LJ)\" \
  NOTARY_PROFILE=\"<notary-profile>\" \
  ./scripts/publish-velopack-mac.sh 1.5.0"'
```
Verify: `spctl --assess --type install -v releases/*osx*Setup.pkg` → "accepted, source=Notarized Developer ID".
> ⚠️ A stale notarized artifact can fool `spctl` — confirm the new artifact's version/date.

### 5.3 Linux — AppImage (new: `publish-velopack-linux.sh`)

**Preferred: native build on the Linux VM** (`ssh tam@172.29.103.99`, dotnet at `~/.dotnet`):
```bash
ssh tam@172.29.103.99 'bash -lc "cd ~/sources/demo/eye-rest && git pull --ff-only && \
  export PATH=\$PATH:\$HOME/.dotnet/tools && ./scripts/publish-velopack-linux.sh 1.5.0"'
```
Smoke-test the AppImage on the VM desktop (`DISPLAY=:10`, not `:0`) before releasing:
tray shows, a popup fires, idle pause/resume works.

**Alternative: cross-compile from Windows** (Velopack supports it) — faster to iterate, but
**must still be smoke-tested on real Linux**:
```bash
vpk [linux] pack --runtime linux-x64 -u EyeRest -v 1.5.0 -e BlinkTwiceEyeRest \
  -p publish/velopack-linux -o releases --category Utility \
  --icon EyeRest.UI/Assets/app-icon.png
```
(after `dotnet publish -c Release -r linux-x64 --self-contained -p:Version=1.5.0 … -o publish/velopack-linux`)

## 6. Upload (all channels → one tag)

Gather every platform's `releases/` on one host (scp the Mac + Linux artifacts to this box,
or upload from each host — `--merge` handles it), then:

```bash
# GitHub Releases (auto-update source of truth) — merges win + osx + linux onto v1.5.0
GITHUB_TOKEN=$(gh auth token) ./scripts/upload-velopack-release.sh 1.5.0

# R2 direct-download page (dl.eyerest.net) — mac zip + win zip/exe + linux AppImage
bun scripts/upload-r2.js
```
`upload-r2.js` now includes the Linux AppImage (`BlinkTwiceEyeRest-linux-x64.AppImage`).
